# 3.1 重构与位置检测说明

后续修正、配置检查与接口整理见 [2026-10-19 整体检查](AUDIT-2026-10-19.md)，最新测试结果见 [验证记录](VALIDATION.md)。

## 已完成的功能与逻辑调整

- **兼容性**：以 Spigot 1.9 API、Java 8 字节码为基线，将标题、ActionBar、粒子名称、材质别名和新旧生物群系接口差异集中到 `ServerCompatibility`。目标覆盖 Spigot/Paper 1.9–26.2；完整验证范围见 [验证记录](VALIDATION.md)，没有逐版本真实上服结论。
- **位置查询**：区域按世界和区块建立索引；玩家留在同一区块时复用候选集合。球体和圆柱体比较平方距离，使用小数坐标；超大区域和索引总量都有内存上限。索引只缩小候选范围，最终边界仍由区域几何判断。
- **触发正确性**：移动时先校验权限和进入检查事件，下一 tick 按真实位置提交成员关系。外层移动被取消、重叠区域拒绝、奖励指令传送玩家时，不继续执行失效位置的进入动作。
- **调度与保存**：使用一个共享同步任务，直接处理待确认玩家和最近到期玩家；区域校准按玩家错开，周期动作保留独立到期 tick。静止玩家跳过几何查询；玩家数据按批次在串行写入线程保存，正常关闭时保存最终状态。
- **功能**：整合 BetterCommands 的首次进入与停留周期动作，增加 UUID 历史、持久化提示开关、区域优先级/启用状态、管理命令、粒子预览、运行计数，以及 PlaceholderAPI 区域快照。
- **配置**：设置、区域和玩家数据拆分为 `config.yml`、`regions.yml`、`players.yml`。旧配置自动备份迁移，重载先完整验证再替换。支持导入 BetterCommands 配置与玩家历史。

## 这轮路径与命名整理

旧根包 `com.github.pregrafer.RegionInformationReload` 改为 `pregrafer.rir`，源码目录、测试目录、导入和 `plugin.yml` 的入口一起更新。保留作者命名空间，避免使用默认包或单独的通用 `rir` 包。Java 包名使用小写；反向域名是命名惯例，并非语法上的必需前缀。[Java 包命名说明](https://docs.oracle.com/javase/tutorial/java/package/namingpkgs.html)

| 原名称 | 当前名称 | 原因 |
| --- | --- | --- |
| `RegionInformationReload` 主类 | `RirPlugin` | 清楚表示插件入口 |
| `MainCommand` | `RegionCommand` | 表达命令所属功能 |
| `DataManager` | `RegionRepository` | 明确配置加载和区域保存职责 |
| `InfoManager` | `MessageDispatcher` | 负责派发消息和指令 |
| `PlaceHolderManager` | `RegionExpansion` | 对应 PlaceholderAPI 扩展 |
| `PlayerMove` | `PlayerMovementListener` | 避免与事件或玩家动作混淆 |
| `RegionAPI` / `RegionAPIImpl` | `RegionApi` / `DefaultRegionApi` | 统一类名大小写和实现名称 |
| `CubeRegion` / `BallRegion` | `CuboidRegion` / `SphereRegion` | 前者实际支持长方体，后者使用标准几何名称 |
| `getRegionSpeed()` | `getRegionCheckIntervalTicks()` | 表明周期含义和 tick 单位 |
| `getInInfos()` / `getOutInfos()` | `getEnterActions()` / `getLeaveActions()` | 内容包含消息与命令，使用动作名称更准确 |
| `getDefaultRedius()` | `getDefaultRadius()` | 修正拼写 |
| `Region.getWorld()` | `Region.getWorldName()` | 返回字符串，区别于 Bukkit 的 World 对象 |

所有包名为小写，类/文件使用 PascalCase，方法/字段使用 lowerCamelCase，常量使用 UPPER_SNAKE_CASE。移除了旧附属使用的无效选点列表、任务映射和消息派发实例包装，保留实际使用的 UUID 选点状态。没有保留旧 API 别名或桥接类。游戏命令、权限、YAML 字段及数据目录维持原有名称；Maven `groupId` 是制品坐标，与源码目录分开。

## 当前周期检测是否合理

目前是事件与周期校准结合，不是纯周期扫描：

1. 移动、传送事件同步检查候选区域的权限，拒绝时取消事件；纯转头跳过。
2. 移动事件结束后，把玩家加入待确认集合；共享任务在下一 tick 根据真实坐标更新状态，再执行进出消息与指令。
3. `regionSpeed` 定期校准未走常规移动事件的路径，以及已在区域内的权限变化。默认每名玩家最多间隔 20 tick，校准相位按玩家轮流分配。
4. `biomeSpeed` 节流群系查询，默认 100 tick；停留动作则使用各自独立的到期 tick。

这种混合方式适合当前同时包含提示、进入限制和停留动作的插件。纯轮询实现简单，但进入提示最多延迟一个周期，玩家还可能在两次采样间穿过整个小区域；无法在移动发生前取消。`PlayerMoveEvent` 提供可取消行为，因此进入限制应保留同步事件检查。[Spigot 移动事件文档](https://hub.spigotmc.org/javadocs/spigot/org/bukkit/event/player/PlayerMoveEvent.html)

旧共享任务每 tick 会复制并遍历所有已跟踪玩家的状态集合。静止玩家虽然不重复做几何测试，仍有 O(P) 的调度遍历成本，P 为在线跟踪人数。2026-09-10 的调度改动已经移除这段全量遍历。移动玩家仍通常发生一次预检查和一次确认查询，两者承担不同职责。

现有自动化测试验证了候选数与行为，不是实际服务器的 CPU、内存或 TPS 基准。是否值得进一步复杂化调度，应结合在线人数、区域重叠程度、移动频率与性能采样判断。

## 已实现的三项组合（2026-09-10）

| 实现 | 收益 | 边界 |
| --- | --- | --- |
| 直接处理待确认玩家集合 | 同一玩家多次标记只处理一次；两个集合轮换复用，回调产生的新标记留给下一 tick | 批次携带会话对象，处理前验证身份；退出、重载或同 UUID 重进后跳过旧会话 |
| 一名玩家一个最近期限 | 用 `TickQueue` 统一管理校准、群系检查和停留动作；只唤醒移动或到期的玩家 | 有序时间桶加反向索引，支持立即取消；不靠堆积过期条目实现取消 |
| 分散周期校准 | 以绝对 tick 相位轮流分配校准时间，避免同批玩家集中校准 | 加入后首次校准在 1–`regionSpeed` tick 内，后续每隔一个周期；总校准次数不因分散而减少 |

队列按到期 tick 排序，每名玩家仅登记三类工作的最早期限，同 tick 的任务在一次玩家更新中完成。期限没有改变时不会重新插入。区域重叠发生变化时，仍停留区域的原周期时钟不重置；离开区域会移除对应周期，重载清空旧队列并重新排期。25、37 等非整秒周期保持精确到期，重载后仍从重建时刻重新计时。

时间桶使用 `TreeMap`，反向索引用于取消与改期；内存随已跟踪玩家数量增长，不按最大配置周期或最大停留周期分配数组。队列更新的最坏复杂度为 O(log P)，每 tick 的处理量取决于实际移动人数和到期人数，移除了必须遍历 P 名玩家的固定成本。在线人数少或每 tick 大量玩家都移动时，不承诺一定比简单遍历更省 CPU。

加入时的位置确认与首次群系采样仍在下一 tick 执行；重载时仍同步静默重建在线状态。这些初始化工作以及同一时刻到期的大批停留动作可以形成峰值，不会为了分散负载擅自推迟进入确认或奖励。Bukkit 的玩家、世界和事件调用继续只在主线程执行。

新增回归验证：空闲 tick 不访问未到期玩家；40 名玩家在默认 20 tick 周期内，每 tick 校准 2 人；重叠区域计时保持；群系和停留动作同 tick 到期；回调中的重载、传送和同 UUID 退出重进；单个玩家更新失败后下一 tick 重试，其他玩家继续处理。队列另有随机改期/取消测试和远期任务反复改期测试。以上是行为与工作量检查，不是生产服性能测量。

`/rir stats` 新增队列人数、累计调度处理次数和累计校准次数，可以对比移动人数、周期设置改变前后的工作量。

## 暂未实现的方向

增加坐骑等事件补充可以减少部分路径的校准延迟，但会增加多版本与事件顺序的复杂度。本轮保留周期校准覆盖这些路径。

普通移动保留即时权限检查。直接删除全部周期逻辑会丢失权限变更校准与停留计时；只在跨区块时检查也不可行，因为区域边界可以位于区块内部。异步读取玩家、世界等 Bukkit API 不适合作为降耗手段；应把异步工作限制在已复制的数据和文件写入上。[Bukkit 调度器文档](https://hub.spigotmc.org/javadocs/spigot/org/bukkit/scheduler/BukkitScheduler.html)

如需检测“单次移动路径穿过区域，但起终点都在区域外”，需要另行定义线段与形状相交的语义，区分步行和传送。它解决的是路径穿越检测，并不等同于调度优化，本轮未实现。
